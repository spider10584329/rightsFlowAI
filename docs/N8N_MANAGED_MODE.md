# Managed automation mode (deployments)

In managed mode the operator runs **one n8n** next to the API, and RightsFlow
provisions, updates and removes every organization's workflows, keys and
schedules itself through n8n's public API. Organization owners and admins only
switch automations on and off in **Settings → Automation**; they never handle
keys, scripts or n8n.

Self-hosted mode (`AUTOMATION_MODE=self_hosted`, keys and
`scripts/setup-n8n-automation.ps1` by hand) stays available for development; see
[N8N_WINDOWS_SETUP.md](N8N_WINDOWS_SETUP.md).

## How it fits together

```
Browser (org admin)                RightsFlow API                         Platform n8n (internal)
  switch on / settings / Run now ─▶ organization_automations             RightsFlow [acme] - A. ...  (published)
                                    automation_reconcile job ──public API─▶ RightsFlow [acme] - E. ...
                                    automation_trigger job ───webhook────▶ "Run on request" trigger
  Runs → Results  ◀── runs, review tasks, deliveries, files ◀──automation API── workflows (organization key)
```

- **Per organization** RightsFlow creates: a managed automation key (only the
  scopes the switched-on automations need) stored in an n8n `httpHeaderAuth`
  credential; a second credential that authenticates the workflows' "Run on
  request" webhook (secret derived from the server's key, never stored); the
  error handler, the hourly health check and one workflow per switched-on
  automation. Names: `RightsFlow [<org slug>] - …`.
- **Templates** live in `backend/app/services/automation/n8n_templates/` and are
  generated by `automation/n8n/build_workflows.py` together with the self-hosted
  exports. Placeholders (`__RF_*__`) are filled in per organization by
  `app/services/automation/provisioner.py`. Bump `MANAGED_TEMPLATE_VERSION` in
  the builder when a template changes; the hourly reconciliation updates every
  organization.
- **Reconciliation** (`automation_reconcile` job) runs after every change and
  hourly for every connected organization (`automation_reconcile_all`). It
  recreates missing or unpublished workflows, applies settings, replaces the key
  when the scopes change or 30 days before it expires (the old key keeps working
  for one hour), and tears everything down when all automations are off or the
  organization is archived. A lease on `automation_connections` keeps two runs
  for the same organization apart; progress is committed after every n8n change.
- **Starting runs:** "Run now" calls the workflow's webhook synchronously.
  Uploads (`statement.uploaded`, `statement.ready`) and requested reviews
  (`review.requested`) queue an `automation_trigger` job that starts the
  workflow about 10 seconds later; one pending start covers every event that
  arrives meanwhile. Schedules are cron expressions in UTC with a stable
  per-organization minute offset.
- **No inbox folder:** managed workflow A only processes statements uploaded in
  the app. Statements uploaded in the app are processed only after a person
  confirms the column mapping (unchanged).
- Successful executions are not stored in n8n (`saveDataSuccessExecution:
  none`); runs and their results are recorded in RightsFlow. Failed executions
  are kept for debugging.

## Operator setup (once per server)

1. **Run n8n** (2.43.5 is verified) where the API can reach it and it can reach
   the API. Keep it on the internal network; only the API needs to talk to it.
   Recommended n8n settings are in `automation/n8n/n8n.settings.env`.
2. **Create the n8n owner** account in the n8n editor, then an **API key** under
   *Settings → n8n API* (no expiry, or rotate it yourself).
3. **Configure the API** (`backend/.env`), then restart it:

   ```
   AUTOMATION_MODE=managed
   N8N_API_URL=http://n8n.internal:5678/api/v1
   N8N_API_KEY=<the n8n API key>
   AUTOMATION_API_URL=http://api.internal:8000   # how n8n reaches this API
   # optional: N8N_WEBHOOK_URL, N8N_HEALTH_URL (derived from N8N_API_URL),
   #           N8N_INSTANCE_ID, AUTOMATION_MANAGED_KEY_LIFETIME_DAYS, AUTOMATION_MANAGED_ROTATE_BEFORE_DAYS
   ```

4. **Run the background worker** (embedded with `RUN_EMBEDDED_WORKER=true`, or
   `python -m app.worker`): provisioning, triggers and the hourly check are jobs.
5. **Check:** an admin opens Settings → Automation, switches *Statement
   processing* on and waits for "On". In n8n, the organization's workflows appear
   published. "Run now" adds a run under Runs.

Upgrading the database: `alembic upgrade head` (migration `c1120d7d8e4a` adds
`automation_connections`, `organization_automations` and
`integration_credentials.managed`).

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| "Automation isn't set up on this server yet" | `N8N_API_URL` or `N8N_API_KEY` missing. Set both and restart the API. |
| Card shows "Needs attention" with "n8n is unreachable" | n8n is down or `N8N_API_URL` is wrong. Reconciliation retries with backoff; **Check again** starts a check at once. |
| "… failed (HTTP 401)" | The n8n API key is wrong or was deleted in n8n. Create a new one and update `N8N_API_KEY`. |
| Runs never appear although workflows are published | n8n can't reach the API: check `AUTOMATION_API_URL` from the n8n host. The hourly health check reports it (Incidents). |
| "Run now" returns 503 | The webhook didn't accept the request (workflow missing or unpublished). A reconciliation is queued automatically; try again a minute later. |
| A workflow was edited or deleted in the n8n editor | Deleted ones are recreated within the hour (or on **Check again**). Edits are overwritten only when the template or settings change; don't edit managed workflows by hand. |
| Old hand-made keys still listed | Settings → Automation → Old keys → Revoke. Managed mode never uses them. |

## Verification

- `backend/tests/test_automation_managed.py`: provisioning, settings, key
  replacement and renewal, drift repair, failures and retries, teardown, archive,
  Run now, upload triggers, run results, access control, template freshness.
- `scripts/diagnostics/n8n_workflow_lint.py`: checks the managed templates against
  the API schema (paths, bodies, credentials, idempotency, triggers).
- Live end-to-end run on 2026-10-15 against a separate n8n 2.43.5 and API: four
  automations switched on in the app → six workflows and two credentials created
  and published; Run now (contract reminders, monthly report, AI review) and an
  upload-triggered statement run all recorded as succeeded; the monthly report
  CSV downloaded from the run's results; a settings change updated the n8n
  schedule; the health check reported n8n, API, key and database healthy;
  switching everything off left no workflows or credentials in n8n.
